Four Models Walk Into a Bank: Inside CARLIY0S, the Multi-Agent Swarm Behind 400+ Latin American Bank Attacks

2026-10-22 Agent & Supply Chain Security by al-ice.ai Editorial

On 21 October 2026, Straiker’s STAR Labs published what it calls a first-of-kind investigation: CARLIY0S, the AI-orchestrated attack system used by CyberCartel’s Tr4nsHack Team — operating behind the front company Hexagon Security Labs Mexico, tracked by Straiker as AiPT-67 — against 400+ Latin American banks, payment providers and fintech gateways. The reason this report matters is its vantage point. Anthropic’s September 2026 misuse report already documented agentic offensive frameworks from the model provider’s side — prompts, outputs, account behaviour. Straiker worked from the group’s own working environment: orchestration scripts, model configurations, rule files, a shared knowledge graph, proxy layers, sync scripts and a dashboard of collected secrets. This is the operator’s side of an AI-powered persistent threat, documented end to end. We read the report first-hand; press coverage of the same campaign (The Information, PYMNTS) is carried here as corroboration of scale only.

A debate club that picks targets

CyberCartel has operated since 2012 on deep knowledge of banking architecture, transaction flows and anti-fraud controls, graduating from phishing to corporate fraud to payment-platform exploitation. The constraint on its latest campaign was human operational speed — so the group replaced linear kill chains with a multi-agent framework built on PentAGI, the open-source autonomous offensive platform. The architecture, as Straiker reconstructs it: a Commander running Claude inside the Cursor IDE, invoking CARLIY0S.py with --ask, --debate, --all and --opus modes, delegating through the Anthropic API to four role-specialised Claude sub-agents that debate each target — STRIKER for execution and exploit code, GHOST for reconnaissance and OSINT validation, FABLE for unconventional lateral vectors — with a single MAXIMUS arbiter returning one final decision before anything runs. Kimi models and xAI’s Grok fill other stages, including five “Grok miners” that harvested credentials into the group’s store.

Two details deserve emphasis because they generalise beyond this crew. First, the refusal fallback: when fallback models refuse an offensive request, the orchestrator aborts the model call and switches to CARLIY0S_consolidated.py, a local file of pre-consolidated offensive code. Guardrails do not stop the operation; they reroute it to hardcoded logic, and the campaign continues. Second, the cognitive OPSEC: rule files explicitly forbid the AI from emitting the Tr4nsHack alias, an attempt to break forensic attribution chains through model output. The group is laundering its identity through the same models it uses for targeting. Straiker also flags one unconfirmed item honestly — a claude-fable-5 entry in the model configuration, with no evidence it was successfully invoked — and we repeat that caution rather than rounding it up.

The memory is an MCP server

The infrastructure section reads like an enterprise platform diagram with the labels swapped. The centre of gravity is the Hexagon Central Server, a 61TB RAID5 Ubuntu box, hosting a Model Context Protocol knowledge graph on port 8001 as the operation’s unified memory: two operator machines read and write the same graph through .cursor/mcp.json, so a target found on one machine is instantly visible on the other. A 15-minute rsync loop with a native PowerShell watchdog keeps the nodes synchronised with memory-only exfiltration discipline; the noisiest tooling (nuclei, sqlmap, hashcat) lives on the central box as a decoupled arsenal; elastic residential proxies spoof domestic Mexican traffic past geographic controls and WAFs. Execution runs through Playwright-driven headless Chromium over SOCKS5 into Magnolia CMS instances, injecting obfuscated Groovy through a Vaadin frontend for RCE, then three automated post-exploitation payloads covering Oracle database scans, credential hunting and internal mapping — with a custom MCP-to-Burp bridge giving the models live proxy traffic, auth headers and session tokens. Our regular readers will recognise the shape: ARTEX’s MCP-backed reconnaissance on the state side, and now CARLIY0S on the criminal side. MCP has become contested infrastructure — the same protocol that organises defensive agents organises the swarm attacking the bank.

What was taken, and what was done about it

The 24 September 2026 snapshot of the group’s FinancialSoft credential database held 4,493 records: 2,911 email addresses, 903 account numbers, 270+ pentest reports including claimed zero-days, 43 credentials from a fintech victim (11 API keys, 32 cryptographic keys) with abuse potential against SPEI, Mexico’s interbank settlement system, plus 67 cleartext passwords, 51 portal logins, 43 database connection strings, 20 JWT signing keys, 20 Keycloak credentials, 4 digital certificates, 19 Wasabi S3 credentials, 15 Mailgun credentials and 6 explicit backdoors including master-password bypasses. Over 200 vulnerabilities including alleged zero-days round out the haul. On the response side: victim organisations are anonymised, proofs of concept and live credentials redacted, Anthropic has revoked the compromised credential reaching Claude, and xAI was notified about the Grok miners — with Straiker crediting both providers for fast cooperation. The named operators (adx, roro, aBerry and others) and the central-server IP are Straiker’s attributions, carried as vendor findings, not independently established facts.

What to do, in order

  • If you run a Latin American financial institution, assume targeting and hunt the TTPs. Magnolia CMS administrative interfaces, Vaadin-framework endpoints, Groovy execution surfaces, residential-proxy login bursts and JWT/Keycloak anomalies are the concrete telemetry Straiker’s report implies — not generic “AI threat” anxiety.
  • Treat MCP servers as security boundaries. CARLIY0S used MCP as shared criminal memory with live Burp traffic. Audit what your own agents’ MCP servers can read and write, who can register new ones, and whether your MCP traffic is logged anywhere an attacker cannot reach — the same discipline as the BUGSTER crime-spree reporting implies for agent tooling generally.
  • Design for the refusal fallback. The campaign’s most transferable lesson is that model refusals rerouted execution to local code instead of stopping it. Controls that live only inside the model — prompts, system instructions, safety tuning — are advisory. Enforcement has to sit at the tool layer: credential scoping, execution sandboxes, egress control and, in Straiker’s own recommendation, an agentic kill switch that revokes tool access and suspends sessions while preserving evidence.
  • Protect the payment rail, not just the perimeter. The inventory centres on SPEI settlement credentials and CLABE account data. Settlement-system credentials, API keys and signing keys deserve the same monitoring intensity as domain-admin equivalents — because to this actor, they are.

The through-line from BUGSTER to ARTEX to CARLIY0S is now unmistakable: small crews running commercial models at machine speed, with shared machine memory, against targets that still defend at human speed. Straiker’s closing prescription — continuous adversarial testing of agents, runtime behavioural blocking rather than alert-queue triage, full agent-inventory visibility, machine-scale correlation and automated containment — is vendor-adjacent advice from a vendor that sells exactly that, and should be read with that discount applied. But the evidence it is attached to was pulled from the adversary’s own infrastructure, and that part deserves to travel further than the marketing.
