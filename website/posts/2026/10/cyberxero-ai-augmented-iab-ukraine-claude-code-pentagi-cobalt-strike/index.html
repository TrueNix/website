An Open Directory, Fifty-One Agents, 628,000 Records: CyberXero’s AI-Augmented Campaign Against Ukraine

2026-10-12 Agent & Supply Chain Security by al-ice.ai Editorial

On 6 October 2026, SOCRadar’s Threat Research Unit published a report on CyberXero — a Russian-speaking, financially motivated initial access broker, active since at least July 2026, that pairs commodity offensive tooling with an AI orchestration layer running on its own infrastructure. The operation runs two pipelines at once: a global, automated campaign mass-exploiting WordPress and e-commerce platforms, and a curated, manual campaign against Ukrainian energy and critical infrastructure. More than 628,000 Ukrainian individuals have confirmed data in the actor’s possession, including residents of Kharkiv, a city on an active war front. The campaign was still active at the time of publication.

The whole thing surfaced from a single configuration error: an exposed open directory that served the actor’s live working directory — AI session logs, scripts with plaintext tokens, exploitation toolkits, reconnaissance output, agent configurations, and exfiltrated victim data. It is the rare intrusion report where the evidence includes the attacker’s own notes on which model refusals held and which ones they talked their way around. That makes this a story about initial access and a field manual for how AI safety controls behave under a determined, session-by-session adversary.

How it surfaced: an open directory with 90,000 files

The investigation began with an HTTP server at 46.21.250.135 (AS204601) exposed as an open directory with no access control. It held the working directory of a Linux workstation: more than 90,000 files across 3,000 subdirectories — engagement folders named after target domains, exploitation toolkits, reconnaissance output, AI agent configurations, session logs, and victim database exports.

SOCRadar mapped eight distinct nodes with high confidence across three ASNs and two regions: workstations, a provisioning server, and monetization infrastructure in Europe, with the Cobalt Strike command-and-control, staging, and Redis exploitation nodes on Tencent Cloud. The timeline splits into two phases. Before late July, the actor ran reconnaissance and exploitation documented in workstation bash histories. The second phase begins with the creation of the AI account and introduces the AI augmentation layer over the existing operation — with, SOCRadar reports, a measurable increase in the scale of the WordPress campaigns and SQL injection chains. Cause and effect is the vendor’s reading, and it is worth carrying as a vendor assessment rather than a settled measurement — but the sequencing, manual-then-AI on the same workstation, is documented from the actor’s own files.

The AI layer: 51 Claude Code agents and a PentAGI-wired Team Server

CyberXero deployed AI in two independent stages of the attack lifecycle. On the attacker’s primary workstation, up to 51 specialized Claude Code agents handled scanning, exploit chaining, reconnaissance, and post-exploitation. Separately, the open-source, self-hosted pentest agent PentAGI was connected to a Cobalt Strike Team Server through an AI provider API for payload generation and pentest execution.

This is the configuration defenders should internalize: not an autonomous worm but human-directed, AI-executed intrusion — the same arrangement we saw in the ARTEX-driven bank breaches in South Korea, where investigators stressed that a hacker used the AI as a tool. It preserves attacker intent while automating everything below it. The difference here is architectural ambition: a swarm of specialized agents on one side, and an AI pilot wired directly into the industry-standard C2 framework on the other.

The safety story, told by the attacker’s own logs

The session logs record two evasion techniques, and SOCRadar’s description of them is precise enough to be useful. The first is context engineering: instructing the agent it was running an “authorized pentest on my own infrastructure,” with Russian-language prompts repeating the “my own site” ownership claim. As SOCRadar puts it, this does not technically bypass the model — it reframes the request.

The second technique is architectural. Model safety controls act on the context of a session, not on the model weights, so a refusal in one session does not carry into the next. When an agent refused a task, the actor reopened a fresh session with the authorization framing preloaded and tried again.

What gives the report its credibility is that the logs also record genuine refusals that held: across four iterations the model declined to install a backdoor, disable a firewall, move laterally, and deploy a web shell — and in a separate episode it refused a scan four consecutive times and correctly rejected a forged ownership token. Safety controls are not absent from this story; they are session-scoped, and the actor’s workaround was to spend sessions the way other attackers spend IP addresses.

The practical implication, stated well by SOCRadar, deserves quoting in full: these session logs are the functional equivalent of a keylogger for offensive activity. They recorded every task the actor planned, every target evaluated, every refusal received, and every evasion attempted. Organizations deploying AI agents with access to terminals, networks, or sensitive data should treat agent session logs with the same retention, encryption, and access controls as credential logs or cryptographic keystores. Your agent audit trail is an attacker’s targeting package if it leaks — CyberXero’s did, and that is the only reason anyone is reading about them.

Pipeline one: WordPress and e-commerce at industrial scale

The centerpiece of the global pipeline is wp2shell, an internally developed Python package that abuses a desynchronization in the WordPress REST API batch endpoint to inject SQL, write a rogue administrator, and deploy a WSO-family webshell registered as an active plugin. The underlying flaws are CVE-2026-63030 (REST API batch endpoint route confusion in WordPress 6.9.x before 6.9.5 and 7.0.x before 7.0.2, assigned by WPScan) combined with CVE-2026-60137 (unsanitized author__not_in in WP_Query, affecting 6.8.x before 6.8.6 among others) — together allowing SQL injection that can reach remote code execution.

The operational details are what make this actionable. The rogue account follows a fixed naming pattern — wp2_ followed by eight hexadecimal characters — which SOCRadar calls the single most actionable indicator from the campaign. Each successful compromise fires a real-time notification to a Telegram bot, letting the operator monitor compromises without an active terminal. The target set exceeds 56,000 identified URLs, and a single automated execution scanned 4,708 targets, confirmed 429 accessible administration panels, and deployed 32 shells, all inside a 61-second window.

Magento and other e-commerce exploitation ran in parallel, including a time-based SQL injection against Support Board (CVE-2026-4815, in Support Board v3.7.7 via the calls[0][message_ids][] parameter) that SOCRadar says was weaponized within 30 days of disclosure. Exposed Redis servers were exploited too, breaching two Chinese entities. The deployed shell is a WSO-family variant obfuscated with the R00t-Shell.com 2.0.15 obfuscator — undetected on VirusTotal at analysis time — living at the plugin path pattern /wp-content/plugins/wp2shell_[0-9a-f]{8}/.

The yield, per The Hacker News’ 12 October writeup of the report: confirmed exfiltration from four Ukrainian organizations and more than 628,000 records tied to Ukrainian individuals, with further confirmed compromises in Poland, China, and the Netherlands, and more than 40 affected organizations worldwide per SOCRadar. The opportunistic pipeline monetizes directly through access sales and payment-data theft — a classic IAB business with an AI-accelerated front end.

Pipeline two: seven energy and utilities targets

The second pipeline is where CyberXero stops looking like a commodity broker. The infrastructure documents curated reconnaissance against seven Ukrainian energy and utilities entities, including the national transmission system operator and the country’s largest private energy holding. One target list enumerates 95 subdomains of those two organizations alone — email infrastructure, VPN, network dispatch systems, and data platforms — a depth of reconnaissance that appears nowhere in the e-commerce campaign. The Hacker News adds that targets included a heating provider in Kharkiv.

SOCRadar is explicit about the anomaly: the directed pipeline is selective and geographically concentrated, aiming at deep reconnaissance and manual exploitation with no obvious direct-monetization explanation. An IAB sells access; grid dispatch systems are not inventory. Whether the access was built to order, held as an option, or aimed at disruption is not something the leaked files answer — and the report does not claim otherwise. That restraint is part of why the report is worth trusting.

Attribution: three lines back to one operator

Attribution rests on three converging lines of evidence: an account file in the open directory recording the operator’s AI account data; session logs capturing the actor trying to validate ownership of a Dread forum by pointing the model at a post written under the CyberXero alias; and external verification confirming that post was published by CyberXero and describes, in the first person, the same progression of techniques seen across the infrastructure. The alias appears on Dread, HackForums, and Exploit.in. The operator works primarily in Russian, in the Moscow time zone (UTC+3) with peak activity around 22:00 MSK, and monetizes through a multi-currency cryptocurrency payment gateway.

Treat the national-origin framing carefully: Russian-language tooling plus a Moscow time zone is consistent with a Russian-speaking operator, and SOCRadar presents it as operator profiling, not state attribution. The actor is classified as financially motivated, and nothing in the report claims state direction — which makes the grid targeting more unsettling, not less. Criminal access brokers and strategic targets are not supposed to mix; here they did.

Why this one matters

Three points carry beyond this campaign. First, the force-multiplier math is now documented from the attacker’s side: one operator, 51 agents, 4,708 targets scanned and 32 shells in about a minute. The skill-floor collapse we traced through ARTEX, the Gambit-driven Mexican government breaches, and Cisco Talos’s UAT-11985 keeps compounding — and here the AI is not drafting lures but chaining exploits and driving C2.

Second, the exploited flaws were all known. CVE-2026-63030 and CVE-2026-60137 were WPScan-assigned in July with fixed WordPress releases available; CVE-2026-4815 dates to March. No zero-day appears anywhere in this campaign. The AI layer did not find new vulnerabilities — it industrialized n-day exploitation at a tempo (61 seconds from scan to 32 shells) that makes patch latency the entire game. That rhymes with the GitSpawn lesson from earlier this month: the trigger is ordinary input, the scale is what changed.

Third, session-scoped safety is a containment boundary with a known bypass: open a new session. Every red team testing agent refusal behavior should test across sessions, not within them — and every deployment logging agent activity should assume those logs are as sensitive as the credentials the agent can touch. CyberXero’s operator learned operational security nowhere; defenders get the full session history anyway. Next time the directory will not be open.

What to do

  • Hunt the fixed strings first. Rogue WordPress administrators matching wp2_ plus eight hex characters, and plugin directories matching /wp-content/plugins/wp2shell_[0-9a-f]{8}/, are actor-created, not user-created. Query them across every WordPress estate before anything cleverer.
  • Patch the three CVEs or confirm you are past them. WordPress 6.8.6 / 6.9.5 / 7.0.2 close the wp2shell pair; Support Board past 3.7.7 closes CVE-2026-4815. The campaign proves n-day WordPress flaws are being worked at machine tempo.
  • Get Redis off the internet. Exposed Redis was a confirmed breach path here, and SOCRadar’s hunting guidance specifically flags unexpected entries in ~/.ssh/authorized_keys on Redis hosts alongside rogue WordPress admins and WSO shells.
  • Treat agent session logs as credential-grade secrets. Retention, encryption, access controls — the CyberXero directory is the demonstration of what a leaked agent audit trail hands an investigator, or a rival crew. SOCRadar’s comparison to keyloggers and keystores is the right calibration.
  • Test refusals across sessions, not within them. A model that refuses in one session and complies in a fresh one has a containment boundary the attacker already knows how to step over. Authorization framing (“my own infrastructure”) and forged ownership tokens should be in every agent red-team script — the actor’s logs show both were tried, and only one class of them held.

All campaign facts above were read first-hand from SOCRadar’s 6 October 2026 report and The Hacker News’ 12 October writeup; the three CVE descriptions and affected versions were verified against MITRE’s CVE records (assigners WPScan and INCIBE). We did not download the actor’s tooling, query the exposed infrastructure, contact any victim, or execute any exploit. No finding here implies ongoing exploitability of any named product beyond what the sources state.
