A Tenant Annotation Decides Where Kubeflow’s Controller Sends Its Cluster Token

CVE-2026-110220, published to NVD on 13 October 2026 and scored 7.1 (CWE-918), lets any namespace tenant who can create a KServe InferenceService name the host that the Kubeflow Model Registry controller talks to — and the controller attaches its own Kubernetes ServiceAccount bearer token to that request. We read the chain first-hand at tag v0.3.17 and at main: the annotation is read unvalidated at controller.go:111, the token goes into the request context at :88-90, and the generated OpenAPI client adds the Authorization header at client.go:420-423. The shipped manifest binds the controller to a ClusterRoleBinding with patch and update on inferenceservices cluster-wide. v0.3.17 is the newest release. There is no fix.

One Annotation Beats Every Flag: Podman’s CVSS 10.0 Sandbox Bypass Was a 2022 Feature, Found by Claude

CVE-2026-94603 reached NVD on 13 October 2026 at CVSS 10.0: any OCI image carrying the io.podman.annotations.checkpoint.runtime.name annotation made podman run silently discard the operator’s own sandbox flags, including --cap-drop=ALL. The cause was a convenience feature merged in December 2022 and shipped in v4.4.0, whose early return skipped the function that applies user security options. The fix is a revert, a breaking change, and a green e2e test turned red. Credited to ADA Logics using Anthropic’s Claude models.
