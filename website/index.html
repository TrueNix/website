Signed Is Not Requested: Apache Airflow CVE-2026-86467 and the Login-CSRF Class Airflow Already Fixed Once

CVE-2026-86467, disclosed 20 October 2026, records a login-CSRF in the Apache Airflow Amazon provider’s AWS auth manager: the SAML login handler discarded the AuthnRequest ID and the callback never required a matching InResponseTo, so an attacker’s signed assertion completes in a victim’s browser and silently logs them into the attacker’s Airflow account. It is the same class Airflow fixed in the Keycloak auth manager six months earlier. We read the advisory, the fix commit and the provider release first-hand.

The Backup App Is the Identity: ConnectWise’s Credential and 300 Microsoft 365 Tenants

On 15 October 2026 an attacker used a compromised credential belonging to the ConnectWise Cloud Backup (formerly SkyKick) application to sign into customer Microsoft 365 tenants from 144.172.64.128, moving tenant-to-tenant seconds apart. Huntress, which broke the news on 16 October, had by 19 October tied nearly 1,000 Entra tenants to the activity with roughly 300 successful sign-ins. ConnectWise shut off Cloud Backup access on 17 October. MFA never entered the picture — application sign-ins have no MFA prompt — and in one tenant a second ConnectWise app granted itself Global Administrator and minted fresh client secrets.
